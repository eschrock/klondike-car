# Phase 4 review, round 1: Shaper SVGs, forms/tiling, STL, zip

Grade: **6/10.** The conventions, geometry, STL and zip are mostly solid. Four defects stop the "cut with confidence" bar (8).
Checked by parsing all 12 Shaper SVGs, the 4 forms and 52 tiles; rendering tiles in Chrome; reading `parts.json`; and unpacking the STLs and a test zip.

## What passed
- Shaper root: `width`/`height` in inches match the viewBox (1 unit = 1 in) in all 12 files. The bounding box of every outline equals the declared size.
- Fills and strokes follow the convention: outside `#000` with no stroke, inside `#FFF` with a black stroke, pocket `#7F7F7F`, guide `#0068FF` stroke. Outside, inside and pocket paths are all closed. No path uses a transform. Engraving paths are open strokes, correctly.
- Holes: #10 = 0.2, sign knob 7/32 = 0.219 (explicit text beats the gauge), 1/4 bolt = 0.266, pin = 13/32 (0.4063). All lie inside their outlines; the nearest wall is 0.37 in.
- Pockets: web dado 0.197 x 0.25 (bulkhead and transom), deck dado 0.512 x 0.25, mortise 0.25 x 0.875 x 0.375. They sit on the face that carries the mate. Transom: L is on the right when seen from the forward face (correct). Bulkhead: L on the left seen from the rear (correct).
- Every outline is convex, so there are no inside corners to worry about. The thinnest wall is the transom mortise floor (0.5 - 0.375 = 0.125, exactly the limit). The thinnest wall to an edge is 0.2.
- Tiles: all 52 have an 8.5 x 11 in page and a window whose viewBox equals its size (1:1). The check square is 1.0000 in. Tile coverage of every drawing is complete. The Chrome render shows the square at 97 px (1.01 in at 96 dpi).
- STL: size = 84 + 50n (3484 bytes, n = 68). The header does not begin with "solid". Every edge is shared by exactly 2 triangles and none runs the same direction twice. The signed volume is positive (165610 and 103506 mm3) and all normals agree with the winding. Units are mm. The clip is 113.3 x 30.7 mm against a 4.5 x 1.25 in hole (0.43 mm per side).
- Zip: Python `zipfile.testzip()` and `unzip -t` pass. CRC, sizes, UTF-8 flag (0x0800), the central directory offsets and zero-length entries are right. The `unzip` CLI cannot create non-ASCII names, but every package name is ASCII.

## MUST fix
1. **Storage lid is cut 0.5 in too small each way.** `storage-lid.svg` is 18.25 x 14.296. The stock in `parts.json` is 18.75 x 14.796, and the joint says "cut size includes the tongue" (0.25 on each of 4 sides). `storage.ts:340` builds the geometry at the visible size (`span([x0+rimW, x1-rimW]...)`) and only `stock` carries the +0.5. `flat.ts` reads the geometry, so the file is the visible panel with no tongue: the frame would not capture it.
   Fix: for a part with `edges: 'captured'` and a stock larger than the pattern, make the outline the stock (or add a tongue) in `flat.ts` or `shaper-svg.ts`. Keep the legend centered. Add a test: pattern bbox >= stock for every Shaper part, otherwise a note that explains the difference.
2. **Web is 0.25 in short at the bulkhead end (no tongue in the 1/4 dado).** From the model: the transom occupies x -10..-9.5 with its dado in the front face, so the web starts at -9.75 (tongue in, deck too). The bulkhead occupies x 49.25..50.75, its dado is in the rear face (x 49.25..49.5), and the deck ends at 49.5. But the web ends at 49.25, flush with the face. The side-web SVG is 59.2399 long (arc length of x -9.75..49.25). Either D-69 moved the bulkhead without moving the web end, or the web needs its tongue.
   Fix: extend the web mesh `xEnd` to 49.5 (the dado bottom), or deepen nothing and state a deliberate 0.25 gap. Re-derive the arc length and the stock (59.34 + 0.1). Add a test: web x-range is at the dado bottom at both ends.
3. **Tiled prints are solid black.** `tileForLetter` embeds the Shaper-style SVG as is, so the outside cut prints as a black fill. In `side-form-B3` the whole page is black and the blue cleat line, dims and drill marks are invisible. This holds for `side-form` (18 of 27 pages overlap the fill), `rail-form` (14 of 14), `crown-templates` and the flap template (marks hidden). It also wastes a lot of ink.
   Fix: in `tileForLetter`, rewrite the paths for print: `fill="none"`, `stroke="#000"`, `stroke-width="0.02"` on `[shaper:cutType="outside|inside|pocket"]`, and keep guides blue (or dark gray) for B/W printers. Pockets could use a light hatch or a 15% gray. Add a test: no tile contains `fill="#000000"`.
4. **Bulkhead cut depth (1.52 in) is more than a Shaper bit can reach.** `bow-bulkhead.svg` outline and hand hole are `shaper:cutDepth="1.52in"` (1.5 in oak). Standard Origin 1/4 in spirals cut about 1 in. Confirm against the exact bit; I am not sure of the longest one. Origin refuses or clamps a depth beyond the loaded bit.
   Fix: either say in the file and the README to bandsaw the outline, cut the hand hole from both faces or in a two-ply layup (2 x 3/4 in with the glue line at mid-plane, each ply a pass), or add a `maxDepthIn` check (default 1.0) that turns the outline into a note. The same rule applies to the 0.895 in flap (fine) and the 0.77 in forms.
5. **The seat-back insert label prints the wrong hole size.** `seat-back-panel.svg` says "insert hole O0.19 x 0.344 deep (x3)". 0.19 is the #10 thread major diameter (`j.diaIn`), not the installation hole for a hex-drive insert (the outside diameter is bigger). A builder who drills 0.19 cannot seat the insert.
   Fix: `kindF === 'blind'` should not label a diameter from `diaIn`. Use the insert vendor's drill size from the sourcing record, or print "drill per insert spec" and no Ø. Keep the 0.344 depth.

## SHOULD fix
- **State the cut face in plain words.** The title says "seen from the -z face" and "+z face" (part-local axes). The transom is "+z face" and the bulkhead is "-z face": neither tells a builder which face is up. Wrong face = a scrapped 1.5 in oak part with the dados on the back. The README only mentions the bulkhead.
  Fix: add a per-file line such as "Cut with the FORWARD (bow-side) face UP; good ply face down" in the title and in `SHAPER_NOTES`. For L/R-merged files (webs, signs, grips) add "2 identical pieces, do not mirror".
- **Keep human text out of the cut files, or guard it.** Each Shaper SVG has 2-40 `<text>` elements, blue-filled: title block inside the part (over the black outline), tags, and notes below the viewBox with `overflow="visible"`. As far as I know Origin ignores text and Studio does not import it as a cut, but I cannot verify it. A blue fill on a text glyph is not a guide (a guide is a blue STROKE), and notes outside the viewBox could enlarge the import extents.
  Fix: put text in a sibling `*-annotated.svg`, or at least wrap it in `<g display="none">`. After the first import, check that Origin shows exactly: outline, holes, pockets, guides.
- **Name the bit for each feature.** The 0.197 web dado is narrower than 1/4 in, so it needs the 1/8 in bit. The 0.25 mortise equals the 1/4 in bit exactly (zero offset), so use 1/8 in. The 0.266 holes are only 0.016 over a 1/4 in bit and Origin may refuse or cut them tight; the 0.4063 pin hole is fine. Origin also needs at least bit-diameter material left in the corner of a pocket.
  Fix: add `bit` to `ShaperFeature` (1/8 below 0.25 wide; holes at or below 5/16 in as drill marks, or 1/8 in bit). Print the list in the file description and a tool plan in the README.
- **The 1/4 in-deep pockets run to 0.375** (mortise, 1/2 in transom, 0.125 floor). Consider 0.3 or a Domino. OK at the limit, but no margin for Origin depth error (+-0.01).
- **Missing deck pin holes.** The seat-pin note says the flat position passes the pin "through the 12 mm deck" into the backer pad, but no deck joint carries it and `deck.svg` has no 13/32 holes. Check the design intent; if true, add the joint with `at`.
- **The sign is a rectangle.** The note says "rounded-oval plank", `sign.svg` is 4 vertices (the model is a `box`). All four edges are banded: the outline is not reduced for the banding (also the 16 in seat back: finished 16, so cut 15.875 before 1/16 in banding). Check with Eric which size the file means, and say so.
- **Engraving.** 1.5 in letters, 16.0 in of ink on an 18.25 in panel, 0.03 in deep (0.76 mm of 4 mm ply: just through the 0.5 mm face veneer): sane. Issues: (a) it is centered by advance width, so the ink is 0.1 in left of center (1.025..17.03, center 9.03 vs 9.125); (b) 0.03 in is within Origin's depth error, so test on an offcut and maybe use 0.04; (c) the README should say "1/8 in straight bit, on-line", because a 60-degree V bit at 0.03 in gives a 0.035 in hairline.
- **Tile alignment marks.** Corner crosses sit at drawing x of the window edge (7.5 on A1, 7.0 on A2), so a cross is never on the same drawing point as its neighbor's cross. The dashed overlap lines are on the other page's crosses, which works but is not obvious. Fix: also draw crosses at the ends of the overlap lines, so both pages carry marks at identical drawing coordinates, and say "overlay A2 so the crosses coincide, then trim".
- **Page count.** 52 pages in total (side 27, rail 14, crown 8, flap 3). The side-form is mostly empty paper and a black web. Better: (a) print line art only (see MUST 3); (b) skip tiles with no ink (compute from the path bboxes: A8/A9 etc. hold only cleat labels); (c) don't print the web outline at all, since the Shaper cuts `side-web.svg`; cut the cleat holes (0.19 in) and the sheer line as an on-line 1/32 in score into the MDF table with the Shaper instead. Same for the rail form: cut it as 3/4 in MDF layers and skip the print.
- **Ramp rib is a knife-edge.** `side-form.svg` S-ramp rib: the profile starts at height 0 and the first inches are under 1/8 in thick. Add a 0.75 to 1 in constant base (or merge it with the table).

## NIT
- 15 degree facets on rounded corners: the sag is 0.021 in on the 2.5 in seat corners and 0.006 on the 0.75 in ones. Fine; use arcs (`A`) for r >= 2 in if cheap.
- The tile page label sits 0.18 in from the page bottom (y = 10.82): some printers clip at 0.25 in. Raise it to y1 + 0.2.
- Rail form: the turn-in dimension line runs to and past the viewBox edge.
- `title` text on the flap and sign is blue on the black outline (unreadable in on-screen previews). Use white or place it outside the part.
- STL: ear clipping gives sliver triangles (68 for a slot: fine). The clip has no insert holes (documented).
- Zip: external attributes are 0 and "version made by" is DOS-only, so the unzipped files get default modes. Fine.
- `shaper:cutType` is redundant with the colors (harmless). `#0068FF` for guides and `#7F7F7F` for pockets are the colors I believe Shaper uses, but confirm with one import before trusting all 12 files.
