# Phase 4 UI: notes (Build tab)

Files: `src/ui/build-panel.ts` + `.css` (the tab), `src/ui/build-helpers.ts` (pure helpers, tested in `build-panel.test.ts`), `src/build/zip.ts` (store-only ZIP, CRC-32, UTF-8 names), `src/build/package.ts` (`BuildData`, `buildPackage`, `zipPackage`). Edits: `right-panel.ts` (the four placeholder tabs became one `build` tab, mounted like Analysis) and `main.ts` (mount, `setDesign` in the cache-key block, `onTab`, and the step filter in `render()`).

## Structure
- Sub-navigation (a nested tablist, arrow keys, Home/End): Verify, Cut list, Nesting, BOM, Shaper, Forms, Assembly, Finishing, Downloads. Each is a `section[role=tabpanel][aria-labelledby]`; only the active one is rendered. The last section is remembered in localStorage (try/catch), as are the verify ticks (`loadDone`/`saveDone`).
- `BuildData(parts, params, {date, link})` computes each output on first use and records `timings`. `buildPackage` forces all of them and returns `files` (`shaper/*.svg`, `forms/*.svg`, `forms/tiled/<id>-<A1..>.svg`, `stl/*.stl`, `cutlist.csv` (the four tables under `# title` lines), `bom.csv`, `README.txt` (date, params hash, link, conventions, file list)).
- Previews are inline SVG (`previewSvg`: root width 100%, height and in-units dropped, clipped to the viewBox); they sit on white so black Shaper cuts read in dark mode. The nesting drawing (`sheetSvg`) uses the true outlines.
- Print: `@page { size: letter; margin: 0 }`; section print hides everything but the active section (details are opened on `beforeprint`); Assembly prints every step (`break-inside: avoid`, so a step never splits across pages). "Print tiled (Letter)" puts the tile SVGs (8.5in x 11in, viewBox 0 0 8.5 11) in `#bp-print-tiles` on `body`, adds `body.bp-print-tiles` (hides `#app`), calls `print()`, and cleans up on `afterprint`.

## Step-through (Assembly section)
The panel emits a `StepFocus {n, visibleIds, highlightIds, view, reframe}` through `onStep`; `null` when leaving the section or tab. `main.ts` stores it and `render()` calls `viewer.update(parts filtered to visibleIds)`, `viewer.highlight(highlightIds, '#ff9f0a')`, and, once per new step (`reframe`), `viewer.setView(viewerView(view))`. A parameter change keeps the step number (`clampStep`), re-emits without reframing. A prep step with nothing installed yet (steps 0 to 3) shows the whole model, no highlight, with a caption. Entering a step clears any truck placement.

## Performance (defaults, browser pane, warm)
Full package 45 to 50 ms (vitest: 47 ms). By stage: verify 1, cut list 6, nesting 1, oak 1, BOM 4, steps 7, finishing 1, Shaper 10, forms 15, tiles 1, STLs 1 ms. DOM render per section 0 to 63 ms (Assembly is the heaviest, 41 kB of text because of the print list). Debounce 250 ms after a parameter change, only while the tab is open; the whole `BuildData` is cached per parameter set (JSON key). The zip is about 1.1 MB (73 files, about 52 of them tile pages), built on click.

## Known gaps
- The viewer has no `under` camera (the running-gear steps ask for it, hull inverted): it falls back to `iso` (`viewerView`). Adding `under` to `VIEW_DIRS` in `viewer.ts` would fix it.
- The step-through filters the parts main builds for the viewer by id; with Transport mode or hidden removables on, hidden parts stay hidden.
- Tile counts are large (the side-form sheet is 27 Letter pages; 73 files in the zip). Only the print dialog was not exercised: `window.print()` was stubbed to check the DOM, the page rule and the 8.5in x 11in tiles.
- Pre-existing: `.sim-panel { display:flex }` beats `hidden` on the Simulation tab panel, so it showed under other tabs; `build-panel.css` carries a one-line `.tabpanels > [hidden]` guard.
- Nothing links Simple view to the Build tab (optional item skipped).

## Build mode (top level)
Supersedes the "Build tab" parts above: Build is now **Simple | Advanced | Build** in the top bar (`#mode-build`, `aria-pressed`), and the Advanced right-panel tab is gone (`right-panel.ts` TABS, `panelHost`). Eric: the narrow right column was too squished.
- **Files:** `src/ui/mode.ts` (+ `mode.test.ts`: `parseMode`, `buildShowsViewer`, history-state helpers), `build-panel.ts/.css` (two hosts: `#build-rail` nav and `#build-main` content), `index.html`, `main.ts` (`setMode`, `chooseMode`, `popstate`), `state.ts` (replaceState keeps `history.state`).
- **Layout (>= 900 px):** grid rail (208 px) | content. Assembly adds a third column: rail | steps (clamp 340 to 520 px) | the **real `#viewer`**, only re-gridded by `#app[data-build-section]` (no second WebGL context; its ResizeObserver reframes). **Below 900 px:** the stacked flex column from style.css: rail (nav and quick actions as two one-line scrollers), then for Assembly the viewer pinned (42vh, max 360 px) with Prev/Next pinned under it, then the content.
- **Viewer elsewhere: hidden** (`display:none`) for every section but Assembly. Those are tables and drawings; a viewer would be a large empty or irrelevant pane and a second thing to scroll past. The view-only toggles (steering, rider, Transport mode, seat, handle, brakes, lights, chocks; class `no-build`) are hidden in Build and reset on entry, because the step-through draws the sled as built.
- **Sections:** nav is a `<nav aria-label="Build sections">` list of buttons (`aria-current="page"`, arrow/Home/End move focus). Cut list tables have real columns (final, rough, grain, fab, step); the BOM has per-section subtotal chips plus a subtotal row; nesting sheets are full width; Shaper and Forms are card grids (Shaper cards now show cut face, bits and a deep-cut flag from `ShaperFile`); Finishing steps are a card grid; Verify runs in two columns. Tables sit in focusable scroll regions.
- **Mode, persistence, history:** `parseMode` (garbage opens Simple). A Build click persists it like Advanced (`klondike-view-mode`); Back, a demo or a light click never does. Entering Build `pushState`s `{klMode:'build'}`, so Back leaves Build for the mode it came from (and restores the saved mode); a click on Simple or Advanced from Build pops that entry (`history.back()` then `setMode`) so there is no dead Back step. The URL hash is still the params only; Copy link does not encode the mode.
- **Leaving Build:** `setActive(false)` emits `stepFocus` null before the render, so the full model returns; the page scrolls to the top; Simple and Advanced CSS and DOM are untouched (the new rail and content are `display:none` there).
- **Print:** section print hides the rail and viewer, shows `#build-main` at full width; tiled Letter print is unchanged (`body.bp-print-tiles`).
- Also fixed: nesting sheets were labeled one too high (`index` is already 1-based).
- **Gaps:** BOM and cut-list tables scroll sideways on phones (the first column stays readable). The step number is not remembered across a reload. Print was checked as CSS only, not through the print dialog.

## Part chips, drawings, structured steps (Eric 2026-10-12: "hard to follow"; every part clickable, with dimensions)
- **Steps:** Assembly, Finishing and Verify (`how`, `passList`) render `goal`, then `items` as a numbered list with nested bullets (`part-ui.ts` `instrList`); the flat `instructions` text is only a fallback. Forms show their `build` list beside the preview.
- **Chips:** every `{{part-id}}` is a button (`aria-haspopup="dialog"`, `aria-expanded`); the ids in `item.parts` that are not in the text trail it as small chips ("+N more" past 5). Cut list names, Verify "Guards" and the nesting parts list are chips too.
- **Popover** (on `body`, `role="dialog"`): name and qty, final T × W × L, the rough cuts from `CutList.cuts`, board, grain, 4 key features, "View drawing", "Show in 3D". - **Show in 3D:** `StepFocus.pin` (`pinFocus`) tints only the pinned part, widens the visible set if its step is later, and asks `Viewer.frameParts(ids)` once (the framing survives resizes until a view button or an orbit). From another section it switches to Assembly at the installing step. "Back to this step's parts" or any step change clears it.
- **Drawings section** (after Forms): `BuildData.partDrawings` (lazy, memoized; the zip has `drawings/<partNo>-<id>.svg`, listed in the README). Drawn after the paint, 700 ms after a parameter change; about 0.4 s at the defaults. A card opens its drawing large in a native `<dialog>` with Download SVG.
- **Cut list:** 1 Cuts by board thickness (qty, rough, piece, note), the resaw pools (`ripText`, `resawHeightText`, `text`), 2 Glue-ups, 3 Finished parts, then plywood and metal.
- **Gaps:** a part hidden inside others (a stub axle) is framed but occluded (use Explode); Finishing items carry no `{{part}}` tokens yet, so no chips there; Shaper parts open their Shaper file as the drawing; the Downloads list waits on the drawings.
